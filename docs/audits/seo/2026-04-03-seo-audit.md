# SEO Audit — 2026-04-03

## Executive summary

- **Crawl signals are coherent:** `app/app/robots.ts` allows public marketing surfaces, lists a sitemap URL built with `getAppOrigin()`, and disallows authenticated app areas including legacy `/calculators`. `app/app/sitemap.ts` enumerates the intended indexable set (home, tools hub, national calculators, 200 state location URLs, alternatives/vs hubs and slugs, resources hub + articles, pricing, changelog, legal) using stable absolute URLs via `getAppOrigin()` from `app/lib/app-url.ts`.
- **Canonical and metadata patterns match the growth plan** on sampled routes: public pages use `getAppOrigin()` for `alternates.canonical` (not raw env), title template `%s | Veld Portfolio` from root `app/app/layout.tsx` except where `absolute` is used (home, changelog), and Open Graph blocks are present on key landings.
- **FAQ JSON-LD** is implemented in `app/components/marketing/calculator-faq.tsx` (`FAQPage` + `Question`/`Answer`) and wired on calculators, location pages, competitor/alternative pages, and resource articles with visible matching copy — aligned with `docs/launch/seo-growth-plan.md` expectations for rich-result eligibility (live validation still required).
- **Gaps vs `docs/launch/seo-growth-plan.md`:** Phase **0.7** — root `WebApplication` JSON-LD in `app/app/layout.tsx` still lacks `operatingSystem` and `offers` called out in the plan to clear Rich Results validation. Phase **3** footer deep links to specific competitor URLs are **not** in `app/components/footer.tsx` (hubs `/alternatives` and `/vs` are); body copy on `/tools` and `/investment-property-calculator` does include Stessa and spreadsheets links — partial vs written acceptance criteria.
- **Operational items** (Search Console, live Rich Results Test, production env `NEXT_PUBLIC_APP_URL` without trailing slash) remain owner verification per Phase 0; not provable from repo alone.

## Severity-ranked findings

### Critical

- None identified in this static/code review.

### High

- None identified. Authenticated shell uses `robots: { index: false, follow: false }` in `app/app/(app)/layout.tsx`, and sign-in/sign-up use `index: false`, reducing accidental indexation of app chrome.

### Medium

- **`WebApplication` JSON-LD incomplete vs Rich Results expectations** — Risk: Rich Results Test may report invalid or incomplete application markup until `operatingSystem` and free `offers` are added. **Evidence:** `app/app/layout.tsx` (`JsonLdScript`), `WebApplication` block has `name`, `url`, `applicationCategory`, `description` only. **Gap vs plan:** `docs/launch/seo-growth-plan.md` Phase 0.7 (`operatingSystem: "Web Browser"`, `offers` with `price: 0`, `priceCurrency: "USD"`).

- **`/contact` intentionally noindex but not in sitemap** — Consistent (noindex pages should not be pushed for discovery). **Evidence:** `app/app/contact/page.tsx` (`robots: { index: false, follow: true }`). Sitemap has no `/contact` entry — **pass** for intentional exclusion; flag only so PM knows omission is deliberate.

### Low

- **Footer internal linking vs Phase 3 written checklist** — `app/components/footer.tsx` links to `/alternatives` and `/vs` (hubs) but not directly to `https://veldportfolio.com/alternatives/stessa` or `https://veldportfolio.com/vs/spreadsheets`. Featured competitor links exist in-page on `app/app/tools/page.tsx` and `app/app/investment-property-calculator/page.tsx`. **Gap vs plan:** Phase 3 acceptance asked for footer entries under a grouped section for those specific URLs — implementation chose hub-level footer links plus in-content deep links.

- **Base calculator footers and Phase 3** — `app/app/tools/brrr/page.tsx`, `str-vs-ltr/page.tsx`, and `fix-and-flip/page.tsx` include ≥2 state variant links each — **matches** Phase 3 calculator-footer criteria.

- **Changelog title uses `absolute`** — Long product-style title bypasses the default template; acceptable for uniqueness; monitor display length in SERPs if needed. **Evidence:** `app/app/changelog/page.tsx`.

- **Staging / preview noindex** — Not determined from repo; preview deployments depend on Vercel/hosting. Call out for deploy verification.
