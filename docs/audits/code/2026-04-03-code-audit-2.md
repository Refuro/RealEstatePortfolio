# Code Audit — 2026-04-03 (Run 2)

## Executive summary

- **Overall:** Significant new code shipped today (embedded mockup components, landing mobile/CTA items, pricing page refinements) — all three plans verified implemented and functionally correct. The codebase is in a healthy post-implementation state with no new security or auth issues introduced.
- **Top risk:** The new `deal-analyzer-mockup.tsx` carries forward **deprecated `border-border/70` and `bg-card/95` patterns** from the real `deal-analyzer-form.tsx` it was designed to replicate, adding 9 new instances of these anti-patterns to freshly committed code. A broader grep confirms the deprecated opacity patterns are systemic across 20+ files — scope was under-counted in the morning audit.
- **Secondary risk:** `uppercase tracking-wide` section labels — explicitly prohibited by design-spec §15.1 and Pillar 6 for anything outside sidebar nav groups and table column headers — are present in 30+ locations across production app code, calculators, and now the new mockup, far exceeding what the morning audit surfaced. This represents a wider design-spec drift than previously documented.
- **Recommendation:** Treat the deprecated-pattern and uppercase-label debt as a consolidated remediation sweep rather than individual file fixes. New code (mockups) should be corrected first as they are the freshest additions.

- **`uppercase tracking-wide` used pervasively outside permitted contexts** — Design-spec §15.1 prohibits `uppercase tracking-wide` for any heading that is not a sidebar nav group label or table column header. Pillar 6 states: "The uppercase-muted label pattern is reserved exclusively for labeling groups of data within a Panel (e.g., sidebar group headers 'TOOLS', table column headers)." A codebase-wide grep finds 30+ violations across: `deal-analyzer-form.tsx` (15+ occurrences for section labels), all four public calculators (`public-calculator.tsx`, `str-ltr-calculator.tsx`, `fix-and-flip-calculator.tsx`, `brrr-calculator.tsx`), `chart-wrapper.tsx`, `deal-analyzer-mockup.tsx` (7 new occurrences mirroring the real form), `lp/investment-property-calculator/page.tsx`, `cookie-preferences-section.tsx`, `mobile-summary-rail.tsx`, `scenario-section.tsx`, and multiple marketing resource/vs/changelog pages. The newly created `deal-analyzer-mockup.tsx` adds 7 fresh instances. — Confirmed across `app/app/(app)/analyze/deal-analyzer-form.tsx`, `app/components/mockups/deal-analyzer-mockup.tsx`, `app/components/marketing/*.tsx`, and others.

- **`border-border/70` / `bg-card/95` systemic scope under-counted in morning audit** — Morning audit found and scheduled these as a hygiene item. This pass confirms they appear in 20+ files, including core production surfaces: `onboarding-panel.tsx`, `mortgage-workspace.tsx`, `modeling-workspace.tsx`, `dashboard/page.tsx`, `paid-intent-checkout-banner.tsx`, `mobile-tool-shell.tsx`, `mobile-section-card.tsx`, `mobile-summary-rail.tsx`, `cookie-consent-banner.tsx`, all four calculator components, `add-property-wizard.tsx`, `property-form.tsx`, and the LP deal calculator page. The scope makes this a coordinated sweep task, not isolated fixes. — Evidence: grep result spanning 23 files.

- **Shadow violations remain open from morning audit; new mockup frames add more** — `app/app/page.tsx` line 304 has `shadow-xl` on the desktop mockup frame. Line 270 has `shadow-lg` on the mobile hero mockup frame. `app/app/pricing/page.tsx` lines 265, 271, 278 each have `shadow-lg` on the "See it in action" mockup frames. `app/app/(app)/onboarding-panel.tsx` line 149 adds a `shadow-lg shadow-accent/25` colored shadow on the primary accent button — a decorative treatment absent from the design-spec shadow system. The morning audit flagged `shadow-xl`/`shadow-2xl`/`shadow-lg` on marketing surfaces; the landing mobile CTA plan explicitly specifies `shadow-lg` for the mobile screenshot frame, suggesting product-intentional use on marketing surfaces that needs a documented exception rather than silent deviation. — `app/app/page.tsx`, `app/app/pricing/page.tsx`, `app/app/(app)/onboarding-panel.tsx`.

- **`design-spec-2026.md` §13.6 stale — PricingCards reference shows deprecated `bg-card/95`** — Section 13.6 documents PricingCards card class as `flex flex-col rounded-xl border bg-card/95 p-4 shadow-sm md:p-5`. The actual `pricing-cards.tsx` correctly uses `bg-card` (no opacity dilution). The spec is stale relative to the live code and could mislead future implementors into re-introducing the deprecated pattern. — `docs/design/design-spec-2026.md` §13.6 vs `app/components/pricing-cards.tsx` line 318.

### Low

- **`next.config.ts` `localPatterns` not removed post-PNG deletion** — The embedded-mockups plan explicitly required removing the `localPatterns` cache-busting entry after deleting the screenshot PNGs. PNGs are confirmed deleted (no `Screen*.png` in `/public/`). But `next.config.ts` line 55 retains `images: { localPatterns: [{ pathname: "**", search: "" }] }`. The broad `"**"` allowall was added to serve the now-deleted PNGs. Whether removal is safe depends on whether any `next/image` still loads local assets (e.g., the `favicon.svg` used as `<Image src="/favicon.svg" ...>` per design-spec §2.3 logo guidance). This should be verified and cleaned up. — `app/next.config.ts` line 54–56; embedded-mockups plan cleanup step #7.

- **`POST /api/billing/portal` — manual body parsing unchanged** — Identified in morning audit as a low-severity consistency item. The route still uses `JSON.parse` + manual `isValidPaidTier` / `isValidBillingCycle` guards rather than Zod `safeParse`. No regression; unchanged from morning. — `app/app/api/billing/portal/route.ts` lines 38–51.

- **`bg-accent/12` non-standard Tailwind opacity in `mortgage-mockup.tsx`** — Line 281: `bg-accent/12` uses an opacity value (`12`) that falls between standard Tailwind steps (10, 15, 20). While Tailwind's JIT compiler generates this correctly, it deviates from the documented token pattern and introduces an inconsistency within the new components. Prefer `bg-accent/10` or `bg-accent/15`. — `app/components/mockups/mortgage-mockup.tsx` line 281.

- **`text-accent` on non-interactive static text in mockups** — `dashboard-mockup.tsx` line 101: `<p className="text-sm text-accent">What do these mean?</p>`. Design-spec §15.1 prohibits `text-accent` for decorative text that is not interactive or a primary CTA. The mockup renders non-interactively (pointer-events-none), so this is a static styled element using accent color for emphasis, violating the rule. The same issue may exist in the real dashboard's link text, but the mockup is newly shipped. — `app/components/mockups/dashboard-mockup.tsx` line 101.

## Risk & impact assessment

- **New deprecated patterns in new code (High):** `deal-analyzer-mockup.tsx` is freshly committed code that violates two explicit anti-patterns from the design spec. Unlike the pre-existing violations (which are legacy), this is a new forward step in the wrong direction. If left uncorrected it normalizes the deprecated pattern for future mockup or component authors who read it as a reference.
- **`uppercase tracking-wide` breadth (Medium):** The spec prohibits this pattern outside sidebar/table headers. It's used in the real `deal-analyzer-form.tsx`, all four calculators, chart-wrapper, and numerous marketing pages. Because the design system labels this an anti-pattern in §15.1, the gap creates cognitive dissonance for implementors reading the spec vs. the code. Risk: future authors continue the pattern because it's dominant in the codebase. No live user-experience bug, but brand consistency and spec authority are eroded.
- **Shadow violations (Medium):** Pre-existing marketing surface shadows remain open from morning audit. The new mockup frames add more `shadow-lg`/`shadow-xl`. The landing CTA plan explicitly specifies `shadow-lg` for the mobile screenshot frame, suggesting this is at least partly intentional for marketing contexts — but no formal design-spec exception exists. Risk: spec ambiguity.
- **`localPatterns` cleanup gap (Low):** The broad allowall `"**"` entry is harmless in isolation but represents an incomplete implementation of the cleanup step from the embedded-mockups plan. Low security risk since these are local static assets; mild ops noise.
- **All three plans fully implemented:** Positive signal — no architectural or security regressions identified from the implementation work today.

## Recommendations (prioritized)

1. **Correct deprecated patterns in new mockup code first (highest priority because it's new code):** Update `deal-analyzer-mockup.tsx` to use `border-border` and `bg-card` (full values) and replace `border-border/70` sections with `rounded-md border border-border bg-subtle/40 p-3.5` (Inset pattern per design-spec §5). Update `mortgage-mockup.tsx` line 243 similarly. This is a small, targeted fix on files created today.

2. **Remediate `uppercase tracking-wide` in production form code:** The highest-impact location is `deal-analyzer-form.tsx` (15+ occurrences). Replace section headings with `text-xs font-medium text-muted` (L5 label, no uppercase) per design-spec §4's "Section labels within content cards" guidance. The calculators can follow in a separate pass. The `chart-wrapper.tsx` and `cookie-preferences-section.tsx` are small files — good targets for quick cleanup.

3. **Document or eliminate marketing surface shadow exceptions:** Either formally document that `shadow-lg` is permitted on marketing mockup frames and product screenshots (adding an exception note in design-spec §6 "Marketing surfaces" row), or soften them to `shadow-md`. The landing CTA plan's explicit `shadow-lg` requirement on the mobile screenshot frame creates an implicit exception that should be reconciled with the spec.

4. **Complete the embedded-mockups cleanup — remove or review `localPatterns`:** Verify whether any `next/image` in the current codebase loads local `/public/` files (specifically `favicon.svg`, any remaining local PNGs). If none remain beyond the SVG logo (which may use `<img>` rather than `<Image>`), remove the `images.localPatterns` entry from `next.config.ts`. If the SVG still needs it, scope the pattern to `/favicon.svg` instead of `"**"`.

5. **Conduct a coordinated `border-border/70` / `bg-card/95` sweep across the 20+ pre-existing files:** These are lower urgency than the fresh mockup violations, but should be batched into a single cleanup PR with the pattern: replace `border-border/70` → `border-border`, `bg-card/95` → `bg-card`, `bg-background/45` → `bg-subtle/40` (the documented Inset background per §5). Key targets: `mortgage-workspace.tsx`, `modeling-workspace.tsx`, `dashboard/page.tsx`, `mobile-tool-shell.tsx`, `paid-intent-checkout-banner.tsx`.

6. **Update `docs/design/design-spec-2026.md` §13.6** to remove the stale `bg-card/95` from the PricingCards reference. Change to `bg-card` to match live code and prevent future authors from reintroducing the deprecated pattern.

7. **`POST /api/billing/portal` Zod schema** — Carry from morning audit. Add a small Zod schema for `returnPath`, `targetPlan`, `targetBillingCycle` to align with route conventions and return structured 400 errors on invalid shapes.
