02 Stack & Token Audit

🟢 What's Working

  • ✓ Geist Sans — Excellent. Used by Vercel, Linear. Clean, geometric, reads trust at any size.
  • ✓ Tailwind CSS v4 — Up-to-date. CSS-variable-based theming via @theme inline is the correct v4 pattern.
  • ✓ Semantic tokens — --background, --accent, --positive, --foreground-muted etc. are all well-named and consistently used throughout.
  • ✓ Dark mode — System preference + explicit override via data-theme. Both paths work correctly. Contrast is appropriate.
  • ✓ Recharts — Reasonable for this use case. Not the flashiest charting lib but stable and well-supported.
  • ✓ Lucide icons — Consistent stroke weight, modern, correct choice for this aesthetic.

🟡 Token Concerns

  • ⚠ Zero brand hue — The accent is #0a0a0a (pure black). No color in the brand vocabulary at all outside semantic red/green/amber.
  • ⚠ Chart colors are all cool-toned blues/teals — chart-1 through chart-5 are all from the same family. No warm accent for differentiation.
  • ⚠ No spacing tokens in CSS — Spacing is documented in the spec but not defined as CSS variables or Tailwind theme extensions. Inconsistencies can creep in.
  • ⚠ Missing interaction tokens — No --ring, no --focus-ring. Focus state uses ring-accent/20 per spec but isn't enforced as a token.
  • ⚠ No motion tokens — No defined transition durations/easing in the token layer. transition-colors and duration-200 used ad hoc in components.

03 Public / Marketing Design
Summary: The landing page is honest, clean, and functional — but it doesn't sell. It reads more like a utility page than a product worth trying. The design says "I exist" but not "you should care." The gap is almost entirely about visual energy and storytelling, not structure.
Hero Section Analysis

The hero is pure centered text: a small uppercase label, an h1 headline, a subline, two CTAs, and three trust pills. No visual anchor. No product visible above the fold on any screen size.

Working

  • ✓ Headline copy is clear and specific
  • ✓ "No card required" trust pills are correctly placed near CTA
  • ✓ Mobile-first flow is clean

Missing

  • ✗ Product screenshot not visible above the fold
  • ✗ No visual anchor or illustration — just text
  • ✗ The `py-12 sm:py-16 md:py-20` padding creates a lot of empty gray space
  • ✗ "Veld Portfolio" label above h1 is redundant — they're already on the site
Benchmark: Stessa, Rentastic, and most modern SaaS landing pages show the product dashboard or a mockup immediately in the hero. The rule of thumb is that users should see what they're signing up for before they scroll. Currently the product screenshot is section 3 (after the hero and calculator section).
Navigation Analysis

The landing nav contains: Calculators, Pricing, Privacy, Terms, Changelog, Sign in, Sign up. Privacy and Terms are legal/utility links — they're cluttering primary nav real estate that should be reserved for conversion-oriented destinations.

Issue: The logo is the text string "Veld" rendered in text-lg font-semibold. There is no brand mark. On a 14-inch laptop at arm's length, this is barely distinguishable from nav copy. Compare: Stessa uses a green wordmark; Rentastic uses a colored logo. Brand mark matters for recall.

Suggested nav: Logo mark · Calculators · Pricing · Changelog · [Sign in] · [Get started →]
Move Privacy/Terms to footer only (they're already there).

Pricing Preview on Landing

The pricing section on the landing page shows three plan names as small rounded-md border border-border bg-card pills, then a "View pricing" button. This is the thinnest section on the entire page.

This section is too weak. Pricing is one of the highest-intent sections on any marketing page. Users who scroll this far are evaluating commitment. Three small pills with text like "Free $0 · 1 property · 5 saved deals" don't convey value — they convey limits. The CTA competes with nothing. This is an opportunity to anchor the "start free" narrative more compellingly.

04 In-App / Dashboard Design
Summary: The in-app design is genuinely well-structured. The information architecture is logical, progressive disclosure is implemented correctly, mobile handling is thoughtful, and the token system keeps things consistent. The issues here are quality-of-life and emotional design — not fundamental problems.
Shell & Navigation

The app shell uses a w-56 left sidebar with sticky positioning, a h-14 header bar, and a full-height nav. Mobile uses a slide-out drawer from the left with a fixed top bar showing the hamburger + logo + UserButton.

Working

  • ✓ Swipe-to-close gesture on mobile drawer (delta < -60)
  • ✓ Focus trap on drawer open (a11y correct)
  • ✓ Route change auto-closes drawer
  • ✓ Sidebar is sticky — doesn't scroll away on long pages
  • ✓ UserButton at bottom of sidebar (account area) is correct placement

Issues

  • ✗ 9+ nav items flat — Dashboard, Properties, Modeling, Mortgage, Calculators, Analyze deal, Deals, Plans, Settings, (Admin) — no grouping or visual hierarchy between primary and secondary tools.
  • ✗ Nav uses text-base (16px) for items — slightly large for sidebar nav. Most modern sidebars use 13-14px.
  • ✗ "Getting started / Add property" is styled as a ghost link (muted) with a Lightbulb icon — it gets lost visually. This is arguably the most important CTA in the sidebar for new users.
  • ✗ No group labels (e.g., "Portfolio", "Tools", "Account") to help users scan quickly.
  • ✗ Logo is just text "Veld" — no icon mark. Contributes to weak brand presence.
Dashboard & Metric Cards

The dashboard follows the spec's "numbers first" philosophy correctly. 5 primary metric cards, a "More metrics" collapsible, charts, and rent-vs-market section. Structure is good.

Working

  • ✓ Primary metrics visible immediately (value, debt, equity, cash flow)
  • ✓ Progressive disclosure via MobileCollapsible for secondary metrics
  • ✓ Cash flow correctly uses positive/negative color
  • ✓ LTV and DSCR show appropriate warning/negative tones
  • ✓ Single-property upsell card at bottom is well-placed and non-intrusive

Issues

  • ✗ MetricCards have no trend data — just a static number with no context of direction (up/down from last month).
  • ✗ All metric cards look identical regardless of importance. Total equity and DSCR use the same visual weight system. The F-pattern "north star" idea is there in theory but not visible hierarchy.
  • ✗ The action row (Add property, Analyze a deal, workspace links) is inside a card but looks like a navigation menu. It blends into the metric cards.
  • ✗ No skeleton loaders matching card shapes — loading.tsx files presumably show blank state.
  • ✗ The "Portfolio summary across X properties" info line is redundant with the page heading "Dashboard" and the metric cards themselves.
Biggest opportunity in the dashboard: Trend indicators. Even a tiny arrow or delta value (+$1,200 vs last estimate) on total equity and cash flow would dramatically increase the "dashboard feel" and give users a reason to return. Right now the numbers are static — there's no story of change.
Visual Hierarchy & Section Pattern Overuse

Throughout the app, sections use rounded-xl border border-border/70 bg-card/95 p-4 shadow-sm. Section headers use text-sm font-semibold uppercase tracking-wide text-muted. These are applied so uniformly that visual hierarchy breaks down at the page level.

The "uppercase tracking-wide text-muted" overuse problem: This pattern appears as: section headers in the app, section headers on the landing page, the "Veld Portfolio" label above the hero h1, the "Try the free calculator" heading, the "What you get" heading, the "See what you get" pricing section header. It's the single most frequently used non-body text pattern in the product. When everything is de-emphasized, nothing is de-emphasized — the pattern loses its purpose.

Recommendation: Reserve this pattern for actual secondary labels inside data-dense sections (chart titles, metric group headers). Use proper heading hierarchy (h2 with meaningful size) for marketing sections and key in-app section titles.

Empty States & Onboarding

The zero-state dashboard uses a centered card with welcome text, a primary CTA, and a <details> element for "More ways to get started". The spec references empty-properties.png and empty-deals.png assets.

Working

  • ✓ Primary CTA "Add your first property" is prominent
  • ✓ Progressive disclosure hides extra options by default
  • ✓ Text is friendly and direct

Missing

  • ✗ The empty state image (empty-properties.png) is not rendered in the dashboard zero state — just text and a button.
  • ✗ No illustration = no brand personality at the most impressionable moment (first login).
  • ✗ The OnboardingPanel is conditional on progress — new users see a panel but its design (unread code) needs review as a moment of delight vs. task checklist.
Pricing Cards (In-App Context)

The pricing card component is among the better-designed parts of the product. The billing toggle, savings badge, current plan ring, and feature list are all well-implemented.

Working

  • ✓ ring-1 ring-positive/60 on current plan is a nice detail
  • ✓ Annual savings context line is helpful and contextual
  • ✓ Mobile collapses features behind MobileCollapsible — good pattern
  • ✓ "Recommended next" badge for Investor (when on free) is correct nudge

Issues

  • ✗ Feature bullets use tiny bg-border dots — not visible enough. Checkmarks (✓) are standard and much clearer.
  • ✗ The recommended/highlighted card doesn't visually pop enough vs. the others. The border-accent/60 ring-accent/30 is very subtle.
  • ✗ On mobile, all three cards stack identically — there's no visual break to make the recommended card stand out.
Micro-interactions & Motion

Current motion usage: transition-transform duration-200 ease-out on the mobile drawer slide. transition-colors on buttons. backdrop-blur-sm on the landing nav overlay. That's essentially the entire motion vocabulary of the product.

2026 benchmark note: Leading SaaS products (Linear, Vercel Dashboard, Notion) use subtle but purposeful micro-animations: hover state transitions on cards, chart reveal animations on mount, number counting on first load, smooth collapsible transitions. Veld has almost none of these. The product feels "instant" but also slightly static and lifeless.

Note: Veld correctly includes app-respect-reduced-motion CSS class for accessibility. This is the right foundation — motion should be additive from this base, not the default.

05 Should You Split the Design Systems?
Verdict: No hard split needed — but apply intentional divergence. The token system (globals.css) should remain shared. The in-app and marketing surfaces should use the same colors, font, and base components. However, the visual expression of those tokens should diverge in a few targeted ways.

🌐 Marketing Site Needs

  • → Larger type scales for headings (h1 at 3xl-5xl is right, but section h2s need more size variety)
  • → More generous whitespace between sections (currently sections feel packed)
  • → Visual variety in section backgrounds (use bg-background for some, bg-card for others, possibly one with a subtle tinted background)
  • → Social proof and testimonial components (not needed in-app)
  • → Feature icons that are more visually prominent (larger, with a color accent, or custom SVG)
  • → A brand accent color used only on marketing (gradient hint, one colored CTA)
  • → More emotional, "wow" copy with visual amplifiers (bold stat callouts, etc.)

📊 In-App Needs

  • → Stays dense and data-first — this is correct for a financial tool
  • → Can remain mostly monochromatic — accent black/white works here
  • → Needs trend indicators and delta values on metrics
  • → Needs sidebar nav grouping/hierarchy improvements
  • → Needs subtle hover/transition polish on cards and rows
  • → Needs empty state illustrations (already designed per visual assets guide)
  • → Feature bullets → checkmarks
  • → Consider a keyboard command palette for power users
The one shared change that helps both: Introduce a single brand accent hue — even a very subtle one. A muted indigo (e.g., #6366f1) or a warm teal (e.g., #0d9488) used for one thing only — the primary CTA button — would give the product a visual identity without breaking the minimal aesthetic. Currently the primary button is pure black, which disappears into the "foreground" token conceptually.

Research finding — 2026 SaaS design principles (SaaSUI, SaaSFrame, Devian):

The dominant themes across all research are: (1) Calm design — less visible by default, more on demand. Veld is already here. (2) Action-oriented dashboards — don't just show data, guide the next action. Veld has the CTA structure but not the visual weight. (3) Emotional design entering B2B — micro-delight, personality in copy, celebration moments. Veld is entirely absent here. (4) Strategic minimalism — every element earns its place. Veld achieves this on structure but not on visual identity.

07 Full Issue Inventory

All identified issues ranked by impact. Surface labels: Public In-App Both

  • I-01
    No brand accent color — accent is pure black/white

    The primary button, active nav item, and key CTAs all use --accent: #0a0a0a. This is functionally the same as --foreground. There is no hue in the brand vocabulary, making everything feel anonymous and hard to visually anchor. Even Robinhood uses a distinctive green.

    High Both
  • I-02
    No social proof on landing page

    Zero testimonials, user counts, star ratings, or trust logos. This is the largest single conversion gap on the marketing site. Users evaluating financial tools need reassurance from other users.

    High Public
  • I-03
    Product screenshot not visible above the fold

    The dashboard screenshot is the 3rd section on the landing page. Users must scroll past a hero and a calculator section before seeing the actual product. For a data-heavy tool, the product screenshot is the most persuasive element.

    High Public
  • I-04
    No trend/delta data on metric cards

    Dashboard metrics show static numbers with no context of change direction. A "+$2,400 equity since last month" delta or small trend arrow would dramatically increase the perceived value of checking the dashboard regularly. This is the core engagement driver missing from the product.

    High In-App
  • I-05
    Uppercase tracking-wide text-muted heading style is overused

    Used as: landing page section headers, hero eyebrow, in-app section headers, chart titles. By the 5th use it reads as visual noise rather than emphasis. Reserve this for secondary structural labels only.

    Medium Both
  • I-06
    Sidebar navigation has no visual grouping

    9 nav items (+ admin) rendered as a flat list. Primary portfolio tools (Dashboard, Properties) share the same visual weight as utility items (Plans, Settings). Adding two or three group labels would dramatically improve scanability.

    Medium In-App
  • I-07
    Logo is a text string only — no brand mark

    "Veld" rendered in text-lg font-semibold in both the landing nav and app sidebar. There is a favicon.svg but it's not used as a sidebar logo mark. At the sidebar's 18px size, the text competes with nav labels. A small icon mark to the left would anchor the brand.

    Medium Both
  • I-08
    Section cadence on landing page is too uniform

    5 sections all share similar bg-card/30 or bg-card/50 backgrounds with border-top dividers. There's no visual rhythm or journey through the page — it reads as one continuous gray block.

    Medium Public
  • I-09
    Feature bullets use invisible dots — not checkmarks

    Pricing card feature lists use <span class="h-1.5 w-1.5 rounded-full bg-border" /> — a tiny border-colored dot that is nearly invisible. Universal SaaS standard is checkmarks (✓) or checkmark icons in green/accent.

    Medium Both
  • I-10
    Landing nav contains Privacy and Terms links

    Primary nav real estate is wasted on legal/utility links (Privacy, Terms). These belong in the footer only. The primary nav should focus on conversion destinations: Calculators, Pricing, Changelog, Sign in, Sign up.

    Low Public
  • I-11
    Empty state on dashboard doesn't use the empty-properties.png asset

    The visual assets guide documents an empty-properties.png illustration specifically for this state. The dashboard zero-state shows only text and a button. The illustration would add personality at the most impressionable moment (first login).

    Low In-App
  • I-12
    Micro-animation and motion vocabulary is near-zero

    Only the drawer slide (200ms ease-out) and color transitions exist. Cards, rows, chart mounts, and number reveals all feel static. This is a quality-of-life gap compared to peer products but not a functional deficiency.

    Low Both
  • I-13
    Sidebar nav text is text-base (16px) — too large for sidebar

    Nav items use text-base with px-4 py-2.5. Most modern sidebars use 13-14px for nav items. At 16px with generous padding, the sidebar nav takes up significantly more vertical space than necessary, making the nav feel bulky when there are 9+ items.

08 Prioritized Recommendations
🔴 P0 — High Impact, Do First
1
Introduce one brand accent hue

Add a single non-black accent color as a new token — e.g., --brand: #6366f1 (indigo) or --brand: #0d9488 (teal, aligned with chart-2). Use it only for primary CTA buttons (Get started, Add property) while keeping all other accents black/white. This is one CSS variable and one Tailwind mapping but fundamentally changes brand presence.

Both High impact
2
Add social proof section to landing page

Add a testimonial or "trusted by" section between the hero and the calculator (or after the screenshot). Even 2–3 quotes from real users with role/context (e.g., "Small landlord, 3 properties in Ohio") is enough. If early-stage, use a "Join [X] investors" count, or a notable endorsement. Position it directly after the hero CTA where trust anxiety is highest.

Public High impact
3
Move product screenshot into (or near) the hero

Restructure the landing hero to include the dashboard screenshot in the lower half of the fold, or just below the CTA buttons. A split-panel hero (copy left, screenshot right) is a proven pattern. Alternatively, use the screenshot as a full-bleed hero background with overlay text. The product needs to be visible before a user has decided to scroll.

Public High impact
4
Add trend indicators to dashboard metric cards

For any metric that changes over time (equity, value, cash flow), show a delta: "+$1,200 this month" in muted text below the value, or a small arrow icon with the direction. This requires storing or computing a previous snapshot for comparison. Even showing "as of [date] estimate" with a trend direction label from the benchmark data would add significant perceived value.

In-App High impact
🟡 P1 — Medium Impact, Next Sprint
5
Group sidebar navigation with section labels

Introduce two or three group labels in the sidebar: Portfolio (Dashboard, Properties), Tools (Modeling, Mortgage, Calculators, Analyze deal, Deals), Account (Plans, Settings). Use the existing text-xs font-semibold uppercase tracking-wide text-muted pattern for these labels (this is a correct use of that pattern). Reduce nav item text to text-sm.

In-App Medium
6
Add logo mark to sidebar and landing nav

Use the favicon.svg already in public/ as a small icon mark (16–20px) to the left of "Veld" in the sidebar header and landing nav. This immediately creates visual brand presence without any design work — the asset already exists.

Both Medium
7
Replace pricing bullet dots with checkmarks

Change the feature list bullets in pricing-cards.tsx from <span class="h-1.5 w-1.5 rounded-full bg-border" /> to a proper checkmark: either a Lucide Check icon at 12–14px in text-positive, or a simple ✓ character. Also apply this to any feature lists in marketing pages.

Both Medium
8
Break the uniform section rhythm on the landing page

Give sections distinct visual personalities: Hero (white background, generous padding), Calculator section (slightly darker subtle background, full-width treatment), Screenshot (full-width with minimal padding, let the screenshot breathe), Value props (white, well-spaced grid), Pricing CTA (dark/inverted background for contrast). The alternating light/dark section pattern is a proven marketing page structure.

Public Medium
9
Remove Privacy and Terms from primary landing nav

These are already in the footer. Removing them from the primary nav frees space for a cleaner link hierarchy: Logo · Calculators · Pricing · Changelog · Sign in · [Get started →]. This also fixes the mobile drawer which currently has 7 links before the auth actions.

Public Medium
10
Render the empty-properties illustration on dashboard zero state

The empty-properties.png asset already exists per the visual assets guide. Add it to the dashboard zero-state card above the welcome headline. It personalizes the first impression and adds visual warmth at a critical onboarding moment.

In-App Medium
🟢 P2 — Quality of Life, Backlog
11
Reduce overuse of uppercase tracking-wide heading style

Audit every instance of text-sm font-semibold uppercase tracking-wide text-muted. Reserve it strictly for: chart titles, in-app section labels within data cards, and table column headers. Elevate marketing section headers to real heading sizes (text-xl or text-2xl) with font-semibold text-foreground.

Both Polish
12
Add subtle hover transitions to metric cards and list rows

Add transition-colors duration-150 and a very subtle hover:shadow-sm or hover:border-border/80 to clickable metric cards. For property list rows, add hover:bg-subtle transition-colors duration-100. These micro-interactions cost zero performance and significantly improve the "alive" feeling of the UI.

In-App Polish
13
Consider a Cmd+K command palette for navigation

With 9 nav items and multiple sub-pages, a command palette would be a significant power-user upgrade. Implement with a keyboard shortcut that surfaces all nav destinations, recent properties, and quick actions (Add property, Analyze deal, New scenario). This is a differentiating feature that most RE tools don't have.

In-App Enhancement
14
Make the recommended pricing card more visually prominent

When signed out, the Investor card gets a barely-visible ring-accent/30 highlight. Increase contrast: use a bolder border, a background tint, or a "Most popular" badge in a more prominent position. The recommended plan should be immediately visually distinct, not subtly different.
