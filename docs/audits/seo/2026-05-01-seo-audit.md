# SEO Audit — 2026-05-01

## Executive summary

- **Overall:** Crawl/index signals stay aligned with intent: `robots.ts` allows `/`, lists production `sitemap` via `getAppOrigin()`, and disallows authenticated app prefixes (`/dashboard`, `/api/`, `/sign-in`, etc.). `app/app/(app)/layout.tsx` sets `robots: { index: false, follow: false }` for the logged-in shell; Clerk auth routes add page-level `noindex`. The sitemap is composed from shared marketing modules (`CALCULATOR_LOCATION_DEFS`, `LOCATION_DATA_US_STATES`, competitor/resource maps, changelog-derived `lastModified`), so indexable URLs stay in sync with data files rather than manual URL lists.
- **Top risks:** (1) Root `WebApplication` + `Offer` JSON-LD monthly prices come from `PRICING_DISPLAY`—drift versus Stripe or copy changes remains a structured-data honesty risk. (2) **`/llms.txt` embeds fixed dollar amounts** for Investor/Pro (`$15/mo`, `$29/mo`) while live pricing can diverge via env overrides (`NEXT_PUBLIC_PRICE_*`). (3) Sitemap `lastModified` is still **changelog-coarse** for most marketing URLs (fine for ops, weak per-URL freshness).
- **Recommendation:** Treat SEO as pipeline hygiene: keep `NEXT_PUBLIC_APP_URL` as the canonical production origin in Vercel, re-validate Rich Results after pricing/schema edits, and run production-only checks (`robots.txt`, `sitemap.xml`, preview `noindex`) on release cadence per `docs/qa/seo-release-checklist.md`.

## Severity-ranked findings

### Critical

- None identified in this static/code review.

### High

- **Root layout JSON-LD `Offer` prices vs billing truth** — `app/app/layout.tsx` builds `WebApplication.offers` from `PRICING_DISPLAY` (`app/lib/pricing-display.ts`). Descriptions reference annual pricing on `/pricing`, but **any** env or product change without updating schema (or narrowing schema) risks misleading rich-result or trust signals.

### Medium

- **`/llms.txt` pricing copy can diverge from env-driven prices** — `app/app/llms.txt/route.ts` hardcodes “Investor ($15/mo, 5 properties), and Pro ($29/mo, 20 properties)” in the About section while `PRICING_DISPLAY` reads `NEXT_PUBLIC_PRICE_*`. If env prices change, **llms.txt** and **schema** can disagree with each other and with the pricing page.
- **Homepage `<title>` vs visible H1** — Title: “Veld Portfolio — Track Your Rental Properties in One Place” (`app/app/page.tsx` metadata). H1: “Replace spreadsheet chaos with one clear view.” Both are on-brand; combined they are slightly less keyword-overlapping than a single primary phrase strategy.
- **Coarse sitemap `lastModified`** — Most marketing URLs share `SITE_LAST_MODIFIED` = latest `CHANGELOG_ENTRIES.date` (`app/app/sitemap.ts`). Legal uses `LEGAL_LAST_MODIFIED`. Editorial or calculator copy edits between changelog posts do not bump individual URLs.
- **Production-only: staging / preview indexability** — Not verifiable from repo; preview hosts should be `noindex` or blocked (Vercel / headers). Call out for live verification.

### Low

- **Footer discoverability on small viewports** — Marketing link row behavior in `app/components/footer.tsx` (per prior audits: some groups `md+`) may weight internal links slightly toward desktop; crawlers still see full HTML.
- **`/llms.txt` not listed in sitemap** — Expected for many sites; discovery is direct URL + proxy allowlist (`app/proxy.ts`). Optional to add only if deliberate.
- **Internationalization** — Single locale (`lang="en"` on `<html>` in `app/app/layout.tsx`); `hreflang` N/A.
- **`keywords` metadata** — Present on `/changelog` and `/about`; low impact today; harmless if accurate.

## Risk & impact assessment

Unresolved **High** items mostly affect rich-result eligibility and perceived pricing accuracy, not sudden de-indexing. **Medium** items affect crawl hints, LLM-facing copy accuracy, and query/snippet alignment. Exposure is organic discovery, social/LLM previews, and schema interpretation on marketing URLs.

## Recommendations (prioritized)

1. **Single source of truth for public prices:** When changing `NEXT_PUBLIC_PRICE_*` or Stripe, update root JSON-LD, `/llms.txt` body, and any hardcoded marketing copy in the same change (or generate `llms.txt` pricing lines from `PRICING_DISPLAY`).
2. **After schema or pricing releases:** Run [Rich Results Test](https://search.google.com/test/rich-results) on `/`, `/pricing`, one `alternatives` page, one resource article with `DefinedTerm`, and one calculator page.
3. **Optional freshness:** Per-URL `lastModified` for high-value `/resources/[slug]` when content changes materially, not only via changelog dates.
4. **Operators:** Confirm production `NEXT_PUBLIC_APP_URL` is the public custom domain (not `*.vercel.app`) so sitemap and robots `Sitemap:` URLs match live canonical origin (`docs/qa/seo-release-checklist.md`).
