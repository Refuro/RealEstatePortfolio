## Severity-ranked findings

### Critical

- None identified in this pass.

### High

- **Oversized client modules — merge and regression risk** — Multiple surfaces far exceed the process guideline (~300+ lines) and bundle many concerns: `app/app/(app)/analyze/deal-analyzer-form.tsx` (~**1234** lines per file read), `app/app/(app)/properties/[id]/projections-tab-content.tsx` (**1288** lines), `app/app/(app)/properties/[id]/mortgage-tab-content.tsx` (**989** lines). *Delta vs Run 3:* file sizes have grown (Run 3 cited ~709 / ~1011 / ~808 respectively), increasing review burden and conflict surface.

### Medium

- **TypeScript error in API route test fixture** — Duplicate property `notes` on the mock property object causes `TS1117` (“An object literal cannot have multiple properties with the same name”) at `app/app/api/properties/[id]/route.test.ts` (lines **61–63**). *Evidence:* `npx tsc --noEmit` from `app/` (exit code 2). This breaks a full-project typecheck; fix by removing the duplicate key.

- **Prisma seed configuration duplication** — `app/package.json` still declares `"prisma": { "seed": "tsx prisma/seed.ts" }` while `app/prisma.config.ts` sets `migrations.seed` to the same command. Same finding as Run 3; risk is confusion and deprecated `package.json#prisma` usage depending on Prisma CLI version.

- **Heavy chart routes — dynamic import without loading UI** — `app/app/(app)/mortgage/mortgage-workspace.tsx` uses `next/dynamic` with `ssr: false` and **no** `loading` option (lines **9–15**), unlike `app/app/(app)/dashboard/dashboard-charts.tsx`, which defines `ChartLoadingPlaceholder` and passes `loading` to `dynamic()` (lines **12–35**). Slightly worse perceived latency vs dashboard pattern.

### Low

- **Cross-major Prisma adapter vs client** — `app/package.json` pins `@prisma/client` and `prisma` at **^6.19.2** and `@prisma/adapter-pg` at **^7.5.0**. The lockfile resolves compatible trees, but version skew is worth monitoring on upgrades. *Evidence:* `app/package.json` dependencies; `app/lib/db.ts` uses `PrismaPg` adapter.

- **API route test coverage remains partial** — Strong coverage in `app/lib/**/*.test.ts` and selected handlers (`app/app/api/properties/route.test.ts`, `properties/[id]/route.test.ts`, `deals/route.test.ts`, `csp-report/route.test.ts`). Most other `app/app/api/**/route.ts` files lack co-located tests; unchanged theme from Run 3.

- **Single scoped ESLint suppression** — `app/app/(app)/settings/theme-toggle.tsx` uses `eslint-disable-next-line react-hooks/set-state-in-effect` with an inline rationale; acceptable if kept narrow.

- **`force-dynamic` on authenticated shell** — `app/app/(app)/layout.tsx` exports `dynamic = "force-dynamic"` (line **10**) with a documented rationale (user-specific banner data). Aligns with architecture guidance when child pages need request-time data; not a defect, noted for performance awareness.
