# SEO Audit — 2026-04-30

## Executive summary

- **Overall:** Indexing signals remain coherent for Veld Portfolio: `robots.ts` allows crawl of public surfaces, disallows authenticated and app-shell paths; `app/app/(app)/layout.tsx` and Clerk sign-in/sign-up add `robots.noindex`; the sitemap is built from shared marketing data modules so new calculators/resources stay aligned when those files update. Root `layout.tsx` provides `metadataBase`, default OG/Twitter, and Organization / WebSite / WebApplication JSON-LD with annotated `Offer` descriptions (monthly prices + pointer to `/pricing` for annual detail).
- **Top risks:** (1) Root JSON-LD `Offer` still encodes monthly prices only—acceptable if descriptions stay truthful, but mismatches versus Stripe/live pricing remain a drift risk. (2) Sitemap `lastModified` uses a single changelog-derived stamp for nearly all marketing URLs, so freshness signals per URL remain coarse. (3) Homepage `<title>` and visible H1 use different headline angles (still valid for brand, slightly softer query/snippet alignment).
- **Recommendation:** Keep SEO as a maintain-the-pipeline discipline: reconcile sitemap counts when location or calculator data changes, validate schema after pricing changes, and run production-only checks (Search Console, live `robots.txt` / `sitemap.xml`) on a schedule.

## Severity-ranked findings

### Critical

- None identified in this static/code pass.

### High

- **Root `WebApplication` + `Offer` JSON-LD vs live billing** — Monthly `price` values come from `PRICING_DISPLAY` (`app/app/layout.tsx`); annual/trial/eligibility live on `/pricing` and Stripe. Descriptions now mention annual pricing on the pricing page, which reduces ambiguity, but **any** env or product drift without a schema update still risks misleading rich-result or trust signals.

### Medium

- **Homepage `<title>` vs H1 wording** — Title: “Track Your Rental Properties in One Place” (`app/app/page.tsx` metadata). H1: “Replace spreadsheet chaos with one clear view.” Coherent for humans; optional keyword alignment if homepage organic targets narrow.
- **Coarse sitemap `lastModified`** — `SITE_LAST_MODIFIED` = latest `CHANGELOG_ENTRIES.date` for most URLs; legal pages use `LEGAL_LAST_MODIFIED` (`app/app/sitemap.ts`). Article or calculator copy edits between changelog releases do not bump individual URLs.
- **Production-only: staging / preview indexability** — Not verifiable from repo; preview hosts should be `noindex` or blocked (Vercel/project settings + live header check).

### Low

- **Footer marketing link row is `md+` in `app/components/footer.tsx`** — Mobile users rely more on `landing-nav` for the same destinations; crawl paths still exist, internal-link weight at page bottom is slightly asymmetric on small viewports.
- **`/llms.txt` is public (proxy) but not sitemap-listed** — Expected; optional to add only if deliberate discovery via sitemap is desired.
- **Internationalization** — Single locale (`lang="en"` on `<html>`); `hreflang` N/A.

## Risk & impact assessment

**High** findings affect trust and rich-result eligibility more than sudden ranking collapse. **Medium** items mostly affect crawl hints and messaging consistency. Exposure is organic discovery, share previews, and schema interpretation on marketing URLs.

## Recommendations (prioritized)

1. **Structured data:** When pricing or tiers change, update `PRICING_DISPLAY` / layout JSON-LD in the same change as product truth, or narrow schema to what you can prove on-page.
2. **Sitemap freshness:** For high-value editorial URLs (`/resources/[slug]`), consider per-URL `lastModified` when content changes, not only changelog-driven dates.
3. **Homepage:** If testing landlord “portfolio tracking” queries, try title/H1 pairs that share one primary phrase without weakening conversion copy.
