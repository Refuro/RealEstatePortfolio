# SEO (Search & Discovery) Audit — 2026-04-07

## Executive summary

- **Crawl and index signals are mostly coherent:** `robots.ts` disallows the authenticated app surface, API routes, and auth pages; `(app)/layout.tsx` adds `robots: { index: false, follow: false }` for the whole app shell; public marketing routes set `alternates.canonical` via `getAppOrigin()` (`lib/app-url.ts`). The sitemap is generated from the same origin helper and lists the intended calculator, comparison, resource, and legal URLs (approximately **223** URLs: 200 state × calculator combinations plus fixed hubs).
- **Structured data is present and aligned on calculator and resource content:** Root layout emits `Organization`, `WebSite`, and `WebApplication` JSON-LD (`app/app/layout.tsx`); calculator and location pages plus resource articles render `FAQPage` JSON-LD from shared FAQ sources (`components/marketing/calculator-faq.tsx`, `lib/marketing/calculator-faqs.ts`), matching visible FAQ copy by design.
- **Top risks remain social preview sameness, sitemap drift for competitor pages, and a robots.txt gap for `/refinance`:** Every page inherits the same OG/Twitter image from the root layout unless overridden; `sitemap.ts` hardcodes `/alternatives/*` and `/vs/*` slugs while resource URLs are derived from data; `/refinance` is a protected app route but is not listed in `robots.ts` disallow rules (unlike `/dashboard`, `/mortgage`, etc.).
- **Recommendation:** Treat **page-specific OG images**, **dynamic sitemap entries from `competitor-data`**, **pricing FAQ JSON-LD**, and **robots disallow for `/refinance`** as the highest-impact follow-ups; verify **Search Console** and **live sitemap/robots** on production after deploy.

## Severity-ranked findings

### Critical

- *(None identified.)* Authenticated routes are protected by Clerk (`proxy.ts`) and noindexed at the app layout; no evidence of secret data exposed as indexable HTML in this pass.

### High

- **Single shared Open Graph / Twitter image for all public pages** — Social previews for pricing, tools, calculators, and articles all reuse `/og-image.png` from root `metadata` (`app/app/layout.tsx`). High-intent URLs do not override `openGraph.images` / `twitter.images`, so shares look identical and may underperform on CTR.
- **`sitemap.ts` hardcodes competitor hub slugs** — `/alternatives/stessa`, `rentastic`, `cozy` and `/vs/spreadsheets`, `excel-rental-property` are literal strings. Slugs for those pages are defined in `lib/marketing/competitor-data.ts`; adding a new comparison page there without updating `sitemap.ts` would omit it from the sitemap (contrast with `getResourceSlugs()` for `/resources/*`).
- **Pricing page FAQ content has no `FAQPage` JSON-LD** — `app/app/pricing/page.tsx` exposes substantive Q&A in the UI (details/summary pattern per prior audits); calculator routes use `CalculatorFaqJsonLd`, but pricing does not, missing FAQ rich-result eligibility on a commercial page.

### Medium

- **`/vs` hub: document title vs H1 mismatch** — `metadata.title` is `"Compare"` (resolves to `Compare | Veld Portfolio`); on-page H1 is **"Veld vs spreadsheets"** (`app/app/vs/page.tsx`). Search snippets and user expectations can diverge from on-page primary heading.
- **`/tools` hub: `openGraph.title` weaker than meta title** — Meta title is `"Free real estate calculators"` (keyword-rich); `openGraph.title` is `"Calculators | Veld Portfolio"` (`app/app/tools/page.tsx`). H1 matches the meta title; social cards do not.
- **`/refinance` not in `robots.ts` disallow list** — Protected route under `(app)` (`app/app/(app)/refinance/page.tsx`) is not named alongside `/dashboard`, `/mortgage`, `/modeling`, etc. Crawlers that hit signed-out redirects waste crawl budget; behavior is mitigated by auth + layout noindex but robots coverage is inconsistent.

### Low

- **Sitemap `lastModified` is always `new Date()`** — Every URL gets a fresh timestamp at build/generation time (`app/app/sitemap.ts`), not content-driven dates. Minor signal noise vs true content freshness.
- **Root `WebApplication` JSON-LD `Offer` prices** — Paid tiers list numeric `price` without explicit billing interval in schema (`app/app/layout.tsx`). Low risk; may be refined for richer merchant/application semantics if desired.
- **Footer omits direct `/pricing` link** — Desktop footer links Calculators, Changelog, Alternatives, Compare, Resources (`components/footer.tsx`); pricing is reachable via nav/CTAs but is not in the footer cluster (minor internal-linking preference, not an orphan).

## Risk & impact assessment

Unresolved **High** items mainly affect **organic CTR** (social and SERP enhancements) and **discovery completeness** when marketing adds new comparison URLs. **Medium** items create **inconsistent messaging** between title, H1, and OG for two hubs and slightly **inconsistent crawler hints** for `/refinance`. Likelihood of user harm is low; likelihood of **missed traffic or weaker previews** is moderate for competitive queries.

## Recommendations (prioritized)

1. **Add page-level `openGraph` / `twitter` images** (or a small set of templates) for pricing, tools hub, each calculator family, and resource articles—keep root defaults as fallback.
2. **Derive `/alternatives/*` and `/vs/*` sitemap URLs** from the same exported slug lists or configs used to render those sections (e.g. `COMPETITOR_ALTERNATIVES`, `COMPETITOR_VS` in `lib/marketing/competitor-data.ts`).
3. **Emit `FAQPage` JSON-LD on `/pricing`** using the same Q&A copy as the visible FAQ, following the calculator pattern (`calculator-faqs.ts`-style single source of truth if duplicated today).
4. **Align `/vs` and `/tools` metadata:** set meta title or OG title to match the primary H1/intent (or adjust H1) for `/vs`; set `openGraph.title` on `/tools` to match the meta title.
5. **Add `/refinance` to `robots.ts` disallow** (or a documented pattern for all `(app)` top-level segments) for parity with other app routes.
