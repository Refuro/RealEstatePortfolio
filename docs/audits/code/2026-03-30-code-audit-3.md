## Severity-ranked findings

### Critical

- None identified in this pass.

### High

- **Oversized client modules — merge and regression risk** — Several surfaces exceed the process guideline (~300+ lines) and concentrate multiple concerns: `app/app/(app)/analyze/deal-analyzer-form.tsx` (~709 lines), `app/app/(app)/properties/[id]/projections-tab-content.tsx` (~1011 lines), `app/app/(app)/properties/[id]/mortgage-tab-content.tsx` (~808 lines). Changes here are high-touch for parallel work and harder to review safely.

### Medium

- **ESLint warnings — dead assignments** — Unused bindings add noise and can hide real mistakes: `scenarioPayoffLabel`, `interestSavedLabel` in `app/app/(app)/properties/[id]/mortgage-tab-content.tsx` (lines ~288–294 per lint); `holdYearCashFlow` in `app/app/(app)/properties/[id]/projections-tab-content.tsx` (~468). *Evidence:* `npm run lint` output from `app/`.

- **Prisma configuration duplication** — `app/package.json` still declares `"prisma": { "seed": "..." }` while `app/prisma.config.ts` also defines `migrations.seed`. Build/tooling may warn that `package.json#prisma` is deprecated in favor of `prisma.config.ts` (per Run 2). *Evidence:* `app/package.json` (lines 20–22), `app/prisma.config.ts` (lines 15–18).

- **Heavy chart routes — dynamic import without loading UI** — `app/app/(app)/mortgage/mortgage-workspace.tsx` and `app/app/(app)/modeling/modeling-workspace.tsx` use `next/dynamic` with `ssr: false` but **no** `loading` placeholder, unlike `app/app/(app)/dashboard/dashboard-charts.tsx` (which uses `ChartLoadingPlaceholder`). Slightly higher perceived latency vs dashboard pattern.

### Low

- **API route test coverage is partial** — Strong coverage in `app/lib/**/*.test.ts` and selected handlers (`app/app/api/properties/route.test.ts`, `properties/[id]/route.test.ts`, `deals/route.test.ts`, `csp-report/route.test.ts`). Many other `app/app/api/**/route.ts` files have no co-located tests; regressions would rely on manual QA or integration paths.

- **Root `tests/` directory** — The repository has **no** top-level `tests/` tree; automated tests live under `app/` (Vitest). Aligns with `app/package.json` scripts but differs from the audit scope wording if contributors expect a separate `tests/` folder.

- **Single targeted ESLint suppression** — `app/app/(app)/settings/theme-toggle.tsx` uses `eslint-disable-next-line react-hooks/set-state-in-effect` with rationale; acceptable but worth keeping scoped.

4. Add **`loading`** placeholders to mortgage/modeling `dynamic()` imports for parity with the dashboard experience.
5. Optionally add **targeted route handler tests** for high-risk APIs (billing, import/export) when those areas change next.
