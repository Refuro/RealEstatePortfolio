# SEO (Search & Discovery) Audit — 2026-04-09

## Executive summary

- Crawl and index signals are coherent: `robots.ts` allows public marketing paths, disallows authenticated app prefixes and auth pages, and references the production sitemap URL via `getAppOrigin()`; `proxy.ts` public routes align with intended marketing surfaces; `(app)/layout.tsx` sets `robots: { index: false, follow: false }` so the authenticated shell is not indexed.
- Indexable routes use `getAppOrigin()` for absolute canonicals; sampled hubs, calculators, programmatic location pages, alternatives, vs, and resources use `alternates.canonical` and Open Graph `url` (relative paths, resolved with root `metadataBase`). FAQ JSON-LD (`FAQPage`) shares the same FAQ item arrays as visible FAQ sections on calculator, competitor, and resource pages.
- Residual risk is mostly **programmatic scale and quality** (hundreds of state × calculator URLs overlapping the national investment-property calculator) and **operational** verification (correct `NEXT_PUBLIC_APP_URL` on production, Search Console, live HTTP status on the long tail). No code changes were made in this pass.

## Severity-ranked findings

### Critical

- None identified in repository review. Auth and app routes are blocked by robots path prefixes and noindex on `(app)/layout.tsx`.

### High

- None identified. Canonical consolidation for the paid LP (`/lp/investment-property-calculator` → `/investment-property-calculator`, `noindex`) is intentional and consistent.

### Medium

- **Programmatic overlap:** `/investment-property-calculator` and `/tools/investment-property/{state}` are both indexable and share calculator intent and FAQ patterns; national page canonicals differ, so this is not a duplicate canonical bug, but search engines may still see **near-duplicate or thin clusters** if on-page differentiation is weak — monitor coverage and queries in Search Console — `app/app/investment-property-calculator/page.tsx`, `app/app/tools/[calculator]/[location]/page.tsx`, `app/lib/marketing/calculator-location-pages.ts` (`basePath` for `investment-property` points at `/investment-property-calculator`).
- **Sitemap freshness signal:** Every URL uses the same `lastModified` (`LAST_MODIFIED` in `app/app/sitemap.ts`), so crawlers get no per-URL recency signal when content actually changes — weaker than section-specific or build-derived dates.
- **Environment-dependent canonicals and sitemap:** `getAppOrigin()` (`app/lib/app-url.ts`) drives sitemap, robots sitemap line, and page canonicals. A mis-set `NEXT_PUBLIC_APP_URL` on a **preview or staging** deployment could emit wrong absolute URLs unless hosting also noindexes those environments (not verifiable from code alone).

### Low

- **Shared OG/Twitter image:** Root `metadata` in `app/app/layout.tsx` defines a single `og-image.png` for Open Graph and Twitter defaults; many child pages do not override images — acceptable for brand consistency but less differentiated in social previews than per-page imagery.
- **Title length on home:** Home uses an absolute title (~55+ characters before brand) — generally fine; other pages use the `%s | Veld Portfolio` template — spot-check truncation in SERP previews if needed — `app/app/page.tsx`.
- **Footer internal links:** Desktop footer links hubs (`/tools`, `/changelog`, `/alternatives`, `/vs`, `/resources`) but not `/pricing` or `/investment-property-calculator` — discovery relies on nav and in-content links — `app/components/footer.tsx`, `app/components/landing-nav.tsx` (not fully audited here).

## Risk & impact assessment

Unresolved **medium** items mainly affect **organic efficiency** (crawl budget on large state grids, possible thin-content perception) and **operational correctness** of absolute URLs if env is wrong — not immediate security or revenue breakage. **Low** items affect snippet richness and marginal internal discovery. Likelihood of env misconfiguration on production is low if deployment checklists set `NEXT_PUBLIC_APP_URL`; preview URLs are the higher-risk surface.

## Recommendations (prioritized)

1. **Production verification:** Confirm `NEXT_PUBLIC_APP_URL` on production matches the apex host (`https://veldportfolio.com` per `next.config.ts` redirect), submit `sitemap.xml` in Search Console, and spot-check index coverage for `/tools/*/*` vs `/investment-property-calculator`.
2. **Sitemap `lastModified`:** Move toward meaningful freshness (e.g. tie changelog or content modules to relevant URL groups, or use build time per section) so large programmatic sets do not all claim the same instant.
3. **Programmatic quality:** Periodically review Search Console “duplicate/near-duplicate” and impression data for `/tools/investment-property/` state pages vs the national calculator; adjust copy, FAQs, or internal linking if Google consolidates or demotes.
