# SEO (search & discovery) Audit — 2026-04-01

## Executive summary

- **Crawl signals are coherent:** `robots.ts` disallows authenticated and API-heavy paths, points `sitemap` at `${NEXT_PUBLIC_APP_URL}/sitemap.xml`, and `sitemap.ts` uses `getAppOrigin()` for stable absolute URLs. Public marketing URLs align with `proxy.ts` public-route allowlist.
- **Indexable marketing pages** generally have explicit `alternates.canonical`, root `metadataBase`, and sensible titles/descriptions; the authenticated app shell is **`noindex` at `app/app/(app)/layout.tsx`**, not only via `robots.txt`.
- **Primary SEO risk:** calculator routes emit **`FAQPage` JSON-LD** (`app/app/investment-property-calculator/page.tsx`, `app/app/tools/*/page.tsx`) but the **FAQ questions and answers are not rendered as visible page content**, which conflicts with Google’s FAQ rich-result expectations and may limit or invalidate eligibility.
- **Secondary gap:** many routes build canonicals with raw `NEXT_PUBLIC_APP_URL` while sitemap uses `getAppOrigin()` (trailing-slash stripping). A mis-set env value could produce malformed canonical URLs (e.g. double slashes).

## Severity-ranked findings

### Critical

- None identified in this repository-based pass (no evidence of public indexable routes returning systematic 404/500 in code review; production HTTP status must be verified separately).

### High

- **FAQ structured data not mirrored in visible HTML** — Rich-result / guideline risk; crawlers may ignore FAQ markup or treat it as ineligible if Q&A are only in JSON-LD. **Evidence:** `app/app/investment-property-calculator/page.tsx` (`FaqJsonLd`), `app/app/tools/brrr/page.tsx`, `app/app/tools/str-vs-ltr/page.tsx`, `app/app/tools/fix-and-flip/page.tsx` — each injects `FAQPage` with `mainEntity` Q&A while the page body shows calculator UI and descriptive copy only, not the same Q&A as an on-page FAQ block.

### Medium

- **Canonical origin normalization split across codebase** — `app/lib/app-url.ts` defines `getAppOrigin()` to strip trailing slashes; `app/app/sitemap.ts` and `app/app/robots.ts` use it, but most page-level `alternates.canonical` values use `process.env.NEXT_PUBLIC_APP_URL || "https://veldportfolio.com"` without normalization. If production env includes a trailing slash, canonicals like `` `${APP_URL}/tools` `` could become `https://example.com//tools`. **Evidence:** compare `app/lib/app-url.ts` vs `app/app/page.tsx`, `app/app/tools/page.tsx`, `app/app/pricing/page.tsx`, etc.

### Low

- **Per-page Twitter metadata** — Root `app/app/layout.tsx` sets global `twitter` cards; some public pages (e.g. `app/app/pricing/page.tsx`) rely on inheritance rather than page-level `twitter`, which is usually fine but leaves key landings without page-specific Twitter overrides if marketing wants distinct share copy.
- **Operational verification not in repo** — Google Search Console property verification, sitemap submission, and staging/preview `noindex` policy are deployment/hosting concerns; cannot be confirmed from source alone. **Evidence:** audit scope limitation.

## Risk & impact assessment

- **FAQ JSON-LD vs visible content:** If search quality systems discount hidden FAQ markup, the main impact is **missed rich results**, not necessarily ranking penalties on core queries; fixing alignment improves eligibility and reduces guideline risk.
- **Canonical env edge case:** Medium likelihood only if `NEXT_PUBLIC_APP_URL` is misconfigured with trailing slash; impact is duplicate or ambiguous canonical signals in edge crawlers.
- **Marketing pages** overall are in good shape for discovery; authenticated duplication is controlled by layout-level `noindex` plus `robots.txt`.

---

## Recommendations (prioritized)

1. **Expose FAQ content on-page** (or remove `FAQPage` JSON-LD) on calculator and investment-property-calculator routes so structured data matches visible Q&A, or switch to a schema type that does not imply an on-page FAQ.
2. **Use `getAppOrigin()` (or equivalent)** everywhere `alternates.canonical` and `metadataBase` are built so canonicals match sitemap/robots origin handling.
3. **Release gate:** when adding public routes, update `app/app/sitemap.ts`, confirm `app/proxy.ts` public matcher, and confirm `app/app/robots.ts` disallow list if the route is authenticated-only.
